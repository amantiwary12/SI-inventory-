  What's built

  The phone page — /scan, no login at any point

  Scan → two big buttons: Take material / Return material.

  Taking: search the list, tap +, set quantity with a stepper. Next screen asks
  four things — name, department (dropdown from your Departments master list,
  with "Other" to type one), returning on (date, defaults to a week out), and
  email (marked optional). Employee ID and a reason sit behind an "optional"
  toggle so the form stays short. Submit → a big reference code like SS-000012,
  and an email copy if they gave an address.

  Returning: type name, email, or the SS- code → see everything out in their
  name → tick what's coming back → done. No code required.

  Admin side — "QR Self-Service" in the sidebar

  The QR code with Print / Download PNG / Copy link, a print stylesheet that
  prints the poster alone (code + three numbered steps), four stat tiles (taken,
  still out, overdue, people), and a plain table of who took what, when, and
  whether it's back. Tabs for Everything / Still out / Taken / Returned. No
  charts.

  How it fits the existing system: each line becomes an ordinary returnable
  ISSUE, so it flows into Pending Returns, the movement log, reports and CSV
  exports untouched. Stock moves on submit, and the same guard applies — nobody
  can take more than is on the shelf. Entries carry selfService: true. Public
  writes broadcast over Socket.IO so your dashboard updates live. Switching the
  module off under Settings → Modules & tools closes the counter, and the API
  refuses self-service writes.

  Two things before it's usable

  1. The sidebar entry needs a seed run — the selfservice module isn't in your

  the word and I'll run it, or run it yourself.

  the dashboard on. For real scanning it needs your office LAN IP or a deployed
  URL.
